Getting started

Add an endpoint path to this backend's base URL:

http://localhost:3000

Locally, run npm run dev inside the backend folder. The default port is 3000.

In Postman, choose the method and enter the full request URL. For JSON request bodies, select Body → raw → JSON. 

Content-Type: application/json
Authorization: Bearer YOUR_ACCESS_TOKEN

Public GET requests do not require a token. Use Postman or the frontend for protected requests and POST/PATCH requests.

Authentication

  1. Create an account using POST /signup.
  2. If email confirmation is enabled, confirm your email.
  3. Log in using POST /login.
  4. Copy the returned token.
  5. In Postman, choose Authorization → Bearer Token and paste the token.
To send a request from Joe to JoeOnn, use Joe's token and JoeOnn's user ID. To accept it, use JoeOnn's token and the friendship row ID.

The backend verifies tokens using Supabase Auth. The authenticated user's ID determines the post author and friend-request sender.

Signup returns a message. Login returns the access token. The frontend removes its stored token on logout. An expired token requires another login.

Request examples

Select an endpoint to expand its instructions.

POST /signup 
{
  "email": "joe@example.com",
  "password": "YourStrongPassword123!",
  "username": "Joe"
}

Use your own email address. Username must contain 3–30 characters and the password must contain at least 8 characters.

Returns 201 with a message. If email confirmation is enabled, confirm before logging in.

POST /login 
{
  "email": "joe@example.com",
  "password": "YourStrongPassword123!"
}

Successful response structure:

{
  "token": "YOUR_ACCESS_TOKEN",
  "user": {
    "id": "YOUR_USER_UUID",
    "email": "joe@example.com"
  }
}
GET /profile

Include your Bearer token. No request body is required.

{
  "message": "Welcome to Joefriends, joe@example.com!",
  "userId": "YOUR_USER_UUID"
}
GET /users

Include your Bearer token. Returns other users' IDs and usernames, excluding the logged-in user. 

[
  {
    "id": "RECIPIENT_UUID",
    "username": "JoeOnn"
  }
]
POST /posts

Include your Bearer token and a JSON body:

{
  "title": "Welcome to Joefriends",
  "content": "This is my first public post!",
  "visibility": "public"
}
  • Title: required, maximum 200 characters.
  • Content: required, maximum 5,000 characters.
  • Visibility: public or friends.

Returns 201 with the inserted post. The backend assigns the author from the token.

GET /posts

Without a token, returns public posts only. With a valid token, also includes your own and accepted friends' friends-only posts. 

[
  {
    "id": 1,
    "user_id": "AUTHOR_UUID",
    "title": "Welcome to Joefriends",
    "content": "This is my first public post!",
    "visibility": "public",
    "created_at": "2026-10-03T12:56:12.87135+00:00",
    "author": "Joe"
  }
]

Posts are returned newest first. An empty result is []. An invalid supplied token returns 401.

POST /friends 
{
  "friend_id": "RECIPIENT_UUID"
}

Use the sender's Bearer token and an actual recipient UUID from GET /users.

Returns 201 with a message and friendship object. Its initial status is pending.

GET /friends

Include your Bearer token. Returns your incoming and outgoing friendship records, including accepted friendships.

Each record contains id, user_id, friend_id, status, and created_at.

PATCH /friends/:id/accept 
PATCH /friends/1/accept
Authorization: Bearer RECIPIENT_ACCESS_TOKEN

No body is required. Replace 1 with the numeric friendship row ID, not a user's UUID.

Only the recipient can accept a pending request. Success returns 200, a confirmation message, and the updated friendship with status accepted.

Privacy rules

Viewer Public post Author's friends-only post
Anonymous visitor Visible Hidden
Logged-in non-friend Visible Hidden
Pending friend Visible Hidden
Accepted friend Visible Visible
Post author Visible Visible

Express verifies authentication. Supabase Row Level Security controls database access using the user's token.

Public posts are available anonymously through the API, although the React frontend's Feed page requires login.

Database relationships

  • public.users.id references auth.users.id.
  • A trigger creates the public profile after signup.
  • posts.user_id references the author's public profile.
  • friendships.user_id is the sender; friend_id is the recipient. Both reference public user profiles.
  • A unique unordered pair prevents duplicate and reversed friendship records.
  • Accepted friendships work in both directions.

Passwords are handled by Supabase Auth and are not stored in the public profiles table.

Error responses

Errors return a JSON message, for example:

{
  "message": "A Bearer token is required."
}
Status Meaning
400 Invalid input, self-friend request, or malformed JSON
401 Missing, invalid, or expired token; unsuccessful login
404 Unknown route, nonexistent recipient, or no matching pending request addressed to you
409 Friendship pair already exists
413 Request body exceeds the configured limit
500 Unexpected server or database error

Testing guide

  1. Create a friends-only post as user A.
  2. Read posts as unrelated user B. The friends-only post should be hidden.
  3. Send a friend request. While it is pending, the post should remain hidden.
  4. Attempt to accept it using the sender's token. The request should be rejected.
  5. Accept it using the recipient's token. The private post should now be visible to the accepted friend.
  6. Test missing tokens, invalid visibility, blank posts, self-friend requests, and duplicate requests.

Check the HTTP responses and database state. Repeat these checks after deployment.
